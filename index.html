1. Understand the Three Tools

Each tool has a different job. They work together.

On your computer

🛠️ Git

Git is a version control system. It records changes to your project so you can track work and return to earlier versions.

  • Tracks file changes
  • Creates commits (saved checkpoints)
  • Supports branches and merging
Online code storage

🐙 GitHub

GitHub hosts Git repositories online. It lets you store code remotely and collaborate with other developers.

  • Stores your repository online
  • Provides backup and sharing
  • Supports pull requests and teamwork
Website hosting

▲ Vercel

Vercel builds and hosts supported web projects. It can watch your GitHub repository and deploy new commits.

  • Builds your website
  • Publishes a live URL
  • Can deploy pushes automatically
Easy memory trick: Git = track changes · GitHub = keep/share code online · Vercel = publish the website.

2. The Complete Workflow

This is what happens when you make a website change.

1. Edit Code VS Code / Computer
2. Commit Save a Git checkpoint
3. Push Send commit to GitHub
4. Build Vercel builds the project
5. Live Updated website URL

3. Essential Git Commands

Run these in the terminal opened inside your project folder. Use Copy to copy each command.

git --version Check whether Git is installed
git init Start tracking a folder with Git
git status See changed and staged files
git add . Stage all current changes
git commit -m "message" Save staged changes as a commit
git push Upload commits to the remote branch
git pull Get and integrate remote changes
git clone REPOSITORY_URL Download a remote repository
git log --oneline View compact commit history
git branch List local branches

4. First Time: Push Your Project to GitHub

Do this when your project is on your computer but not yet on GitHub.

Create a Repository on GitHub

Sign in to GitHub → Click New repository → Enter a repository name → Choose Public or Private → Click Create repository. For an existing local project, avoid adding a README or .gitignore on GitHub at this stage if you want the simplest first push.

Open Your Project in VS Code

Open the project folder, then choose Terminal → New Terminal. Make sure the terminal is inside the correct project directory.

Initialize Git and Commit Files

git init
git add .
git commit -m "Initial commit"
git branch -M main

Connect Your Local Project to GitHub

Copy the HTTPS repository URL from the GitHub repository page. Replace the example URL below with your own URL. 

git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git
git push -u origin main

Sign in or authorize GitHub if Git asks. Refresh the GitHub repository page; your project files should appear.

If you already pushed your project to GitHub: Skip this section. You do not need to push it again just to connect Vercel.

5. Connect GitHub to Vercel

One-time setup: link your GitHub repository to a Vercel project.

Open Vercel and Sign In

Go to vercel.com. Sign in using GitHub if possible. If asked, authorize Vercel to access the GitHub account or repositories you want to deploy.

Import Your GitHub Repository

From the Vercel dashboard, click Add New → Project (or Import Project). Under Import Git Repository, find the repository you pushed to GitHub and click Import. If it is missing, check the GitHub permissions / repository access in Vercel.

Check Project Settings

Vercel usually detects popular frameworks automatically. Confirm the Framework Preset, Root Directory, Build Command, and Output Directory for your project. For a simple static HTML/CSS/JS website, select the appropriate Other/static configuration and make sure the HTML entry file (commonly index.html) is in the deployed root directory. Do not copy settings blindly from another framework.

Deploy

Click Deploy. Vercel installs dependencies if needed, runs the build (if configured), and publishes the result. When deployment succeeds, open the generated .vercel.app URL.

Confirm the Git Connection

Open the Vercel project → Settings → Git. Confirm the correct GitHub repository is connected and note the Production Branch (commonly main).

Important: You connect the repository to Vercel only once. After that, pushes to the connected production branch can trigger production deployments automatically.

6. Every Future Update: Edit → Push → Live

Once GitHub is connected to Vercel, this is your normal routine.

Example: You changed your website heading in VS Code

Run These Three Commands

git add .
git commit -m "Updated website design"
git push origin main

What happens next?

  1. Git sends your new commit to the GitHub main branch.
  2. Vercel detects the new commit in the connected repository.
  3. Vercel starts a deployment and shows its status in the Deployments tab.
  4. If the deployment succeeds, the Production URL serves the new version.
Branch rule: A push to the configured Production Branch (often main) normally creates a Production Deployment. A push to another branch usually creates a Preview Deployment. Your Vercel project settings determine the exact behavior.

7. If the Website Does Not Update

Check these points before changing settings.

Deployment Failed

Vercel → Project → Deployments → Open the latest deployment → Inspect Build Logs. Fix the reported error, then commit and push again.

Wrong Branch

Check Vercel → Settings → Git → Production Branch. Make sure you pushed to that branch if you expect a production update.

Wrong Repository or Folder

Confirm the connected GitHub repository and Vercel Root Directory. Your website files must be inside the configured project root.

Old Version Still Visible

Open the latest successful deployment URL, refresh the browser, and check whether the Production domain points to that deployment.
